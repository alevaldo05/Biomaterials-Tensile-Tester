# Tester app and shared packages

Feature card. Update it in the same change as the feature.

## Purpose
The React and TypeScript app for running tests, the packages it shares with the website, the back end, and the containers. Design: [ARCHITECTURE](../../app/ARCHITECTURE.md). The website pages do not need any of it to run.

## Files
- `docs/app/ARCHITECTURE.md`
- `docs/app/FEATURE-STATUS.md` (what is implemented, simulated, untested, unsupported; update it with every stage)
- `packages/ui/` and `apps/tester/`: the graph and screen pieces, and the app itself (controller, screens, exports)

## What the user sees
- On the website: New Test says "Download not yet available" until the owner publishes a Windows release
- In the app (`npm run app`): menu Home · Test · History (signed in) · Device · Help · Settings (· Admin for admins), and a status bar with six separate indicators (Device, Data, Calibration, Recording, Local storage, Lab server), never one "Ready"
- Save data menu (after a test; `components/SaveMenu.tsx`): focus moves to its first item, Up/Down/Home/End move between items, Esc closes it (nothing is sent to any device) and focus returns to the Save data button; Tab and Shift+Tab close it and move on, and a click or tap outside closes it ; required setup fields read as "(required)" to screen readers, with the red asterisk still hidden from them. The menu keys are checked in the source by `apps/tester/test/app-checks.test.ts`; Tab, a click outside, and Esc were also tried in Chromium after a test recorded from a stand-in device (not a real board).
- Buttons, text boxes, dropdowns, the password box and the segmented choice use a border (`--control-line`: `#6b7a70` light, `#7a8c81` dark) that is at least 3:1 against the page, surface, and panel backgrounds (WCAG 1.4.11); quiet and link buttons and the menu buttons stay borderless; checked by a contrast test in `apps/tester/test/app-checks.test.ts` and by screenshots in Chromium
- Keyboard: the first Tab stop is a "Skip to main content" link; changing screens sets the tab title (for example "Help · Biomaterials Tensile Tester") and moves focus to the screen's main part; at 1100 px and narrower the closed Setup drawer cannot be reached with Tab, focus moves into it when it opens, and Esc closes the open one (it sends nothing to any device) and returns focus to Setup; with reduced motion set on the computer, animation and smooth scrolling are off everywhere. Tried with Tab in Chromium at 1366, 1024, 768, and 390 px only.
- Home ("Split with tiles"): a New test tile, then Load test, Test methods, Recent tests, Device and calibration, Reports and exports; on the right, interrupted recordings to recover (Open it, Download, Mark as handled) and Recent tests (this computer and the lab server)
- CSV files the app and the website write put an apostrophe before any cell that starts with = + - or @ unless the whole cell is a plain number (so a note such as `-2+cmd|...` cannot run as a formula in Excel); the same rule is in `packages/core/src/csv-write.ts`, `calibration.ts`, and the website's `live-csv.js`, `compare.js`, and `calibration.js`
- Print report (Draft, white paper, nothing saved) is in Save data after a test, on Load test, and on Compare tests
- After a test: Show regions and Tangent line at cursor under the graph (display only; the tangent's slope is fitted over nearby points)
- Device → Check the calibration with known weights: typed readings or Read force (the calibrated force averaged over 1 s); errors, tolerance flags, fitted line, CSV, Copy, Print; changes nothing (`calibration-check.ts`, `pages/CalibrationCheck.tsx`)
- Load test → Compare tests: up to 12 tests of one test type (files or recent tests); an overlay graph where each test keeps its colour and line style (4 hues checked for colour blindness × 3 line styles, legend inside the picture), key results per test with the mean and sample SD, warnings (different materials, no specimen ID, CSV imports, example dimensions, no data), summary CSV (text cells through the shared `csvCell`: formula guard and quoting as in the other CSV files), Copy summary, graph PNG/SVG; a CSV file's material and specimen ID are read from its header lines (`apps/tester/src/compare.ts`, `pages/Compare.tsx`; `SERIES_LIGHT`/`SERIES_DARK`/`seriesStyle` in `packages/ui/src/Graph.tsx`)
- Test (one window, the approved "Version C" layout): on the left a Quick settings panel with five parts (Test, Specimen, Connection, Setup file and calibration, Before you start; each has its own Need help text) that folds to a slim rail (Locked, specimen ID) while recording and after the test until New test and can be opened again from the rail; at 1100 px and narrower it is a drawer opened with Setup (Esc closes it, sends nothing, and focus returns to Setup); in the middle the graph card with the view switch (a dropdown on phones), a data-source tag, and an action bar: Zero force (the software baseline), Start recording or End recording, then Save data and New test, and the line "Move and stop the crosshead on the tester's own controller. This app only records."; on the right the live readouts (Force, Displacement, Stress, Strain, Elapsed; a missing value is a dash; uncalibrated values are volts) or, after the test, Key results and Session details (under the graph at 768 px and narrower); along the bottom the Specimens strip: tests finished since the app was opened (from their own records, never invented; `run-tests.ts`) and the one recording or next. Start recording stays unavailable with the reason shown under it until everything is ready
- No equations on the Test screen: plain axis titles (Stress (MPa), Strain (mm/mm), Force (N), Displacement (mm), Time (s)); key results show a name, a value, and a unit (Modulus estimate, Ultimate tensile strength, Strain at ultimate strength, Strain at failure (estimate), Energy to failure; relaxation results likewise), each with an "i" button ("About …") that shows its definition and caveats; the CSV, Excel, and report rows keep their full wording (`results.ts`: `rows` for files, `screen` for the Test screen)
- Theme: Light, Dark, or Follow system (the default; follows the computer's setting live), chosen in Settings and remembered on this computer (`theme.ts`, key `app-theme`); the website's default green only
- Load test (session files and CSV; simulated files are refused (also a session file marked real whose calibration is marked simulated) (a CSV's `Source` note is read with optional quotes and a comma, semicolon, tab, or colon, and the loaded record is checked again); imports are labeled as unverified; rows of a CSV that are empty, text, or hex-style (`0x10`) are left out and counted, with a notice under the file description saying how many; Print report opens the browser's print window with a Draft report on white paper, nothing saved), Test methods (saved setups with revisions, on this computer and, when signed in, on the lab server; only admins change lab methods), Device (connection, calibration, a copyable diagnostic summary), Help (searchable, offline; ends with the line "Version <v> · built from <commit> · shared website files <first 12 of the hash>", which wraps on a phone), Settings (theme: Light, Dark, Follow system; recordings kept on this computer). These screens keep their earlier look inside the new header (a green underline on the current menu item); a second pass will restyle them
- A Need help button at the bottom right of every screen with help for the current screen or part of the quick settings; at 768 px and narrower it sits at the end of the page instead of floating, so it never covers a button or a reading
- The app has no tester buttons and the line "Move and stop the crosshead on the tester's own controller. This app only records."

## Behavior to keep
- The website stays plain files with no build; nothing under `packages/`, `apps/`, `firmware/`, or `deploy/` is published to GitHub Pages
- The app sends no Start, STOP, Tare, speed, or position command to the tester
- Machine control stays "unsupported" (sends nothing) until the tester's interface is verified and reviewed
- `packages/core` gives the same results as the website's scripts (same CSV header lines, so files open on either side); a calculation changed on one side is changed on the other in the same change
- Graph, calculation, and recording code never import a device adapter, a transport, or the wire protocol (a test checks this)
- A calibration is used only when its whole signal path matches; without one, values stay in volts and no stress or strain is calculated
- After a fault or a device restart, Disconnect and Connect are both offered; Connect closes the old connection before opening the port again and sends nothing to the device. A finished test keeps its session file through a new Connect or a Disconnect (the file no longer needs a connection)
- A test's session file and journal entry carry the device profile and calibrations in use when Start recording was pressed; choosing another setup file after the test does not change them
- Board pins, the I2C address, and channel wiring live only in the firmware's `board_config.h`, all marked as examples; the firmware sends raw counts only and understands only the six acquisition requests
- Recording never depends on the back end; the website never needs it
- The lab server answers 409 for the same file saved twice by the same person, 429 beyond 30 saves a minute for each person, and 400 for arrival times outside the years 2000 to 2100; a cookie it cannot decode counts as signed out; sign-ins that ran out are cleared at sign-in (the app shows the server's message); a sign-in attempt is counted before its password is checked (parallel guesses cannot pass the 5-in-15-minutes limit), and a full table of counts drops run-out and unpaused entries first instead of clearing every pause. The lab server refuses simulated tests and files with lines a device does not send; it labels each saved test's calibration (lab-approved, not from the lab, none) and shows it in History
- The Windows app keeps context isolation, the sandbox, and no Node in the screens; its preload exposes only a fixed label, the two lab-address calls, and the seven journal calls (all checked in the main process); the lab server is a data connection only (screens always come from the installation) and the sign-in never reaches the screens; it loads only its bundled screens; the installer is a draft release published only by the owner (checked by `apps/desktop/test/desktop.test.ts`); the first installer build succeeded on GitHub (draft `app-v0.2.0-beta.1`) but has never been installed on a Windows computer (first-install checklist in `docs/app/WINDOWS-APP.md`); code signing is not planned; version 1 is `1.0.0-beta.1` and the workflow builds an unsigned installer and an unsigned portable `.exe` (the portable one is untried; neither has been built at this version yet); the version is written only in `apps/desktop/package.json`; the Help screen's build stamp and the workflow's release notes show the same line; every website file the app's build or the reference tests read is in `scripts/shared-files.js` (a test checks this)
- A comparison never invents a value: a missing result shows a dash and is left out of the mean and SD; the offset yield is labelled an estimate
- The app has real acquisition and replay of saved sessions only: no simulator in its source or build
- While recording, samples are committed to this computer's storage about once a second; an unfinished recording is offered for recovery on Home; a failed save is shown and recording continues in memory
- A recording ended by a fault, a device restart, or a lost connection stays interrupted: its session file keeps the fault and restart lines in order and writes `interrupted`, `endReason`, and `events`; Load test and recovery show it as interrupted (older files without these fields still open). Which received lines are kept is decided from the parsed message type, never from the line's text
- A software baseline is not a machine tare and not a calibration, and the screen says so; it is saved with the test (`forceZero_N` in the session file and the journal entry, also in the Windows app's journal files) and subtracted again when the test is reopened, so the results match; older files without it open with no baseline
- Each container is replaceable on its own: no service waits for another, and the gateway looks addresses up per request
- `.env` and backups are never committed; images are not published without the owner's okay
- Roles are checked on the server; View as user changes only the screen
- Calibrations are stored only for real equipment, are never overwritten, and are used only once approved; migrations only add
- The serial speed is 921600 in both `board_config.h` and `apps/tester/src/real.ts`
- The USB serial transport is untested with real hardware, and the docs say so until it has been tried
- The saved reference numbers change only when a website calculation is changed on purpose (`npm run reference:update`)

## Labels that must stay
- "Simulated data, not measured" on anything from the simulator (in the app, only in tests)
- Speed and hold time are labeled as instructions for the operator; the app does not set them
- No software button is called an emergency stop

## How to check
- `bash firmware/common/test/host/build-and-test.sh` (needs a C++ compiler); `pio run -e esp32dev` in `firmware/esp32-ads1115` (needs PlatformIO and its download hosts); the `firmware-build` job in `.github/workflows/app.yml` builds every `firmware/*/platformio.ini` on GitHub (compile only, no board named; each platformio.ini pins its own platform; the ESP32 one is `espressif32@8.0.0`)
- `npm run app:build`, then open each screen in Chrome at 1366, 1280, 1024, 768, and 390 px, light and dark; recording, recovery, and Load test are covered by `apps/tester/test/` with a stand-in device
- `npm install` once, then `npm test` and `npm run typecheck`
- `node scripts/check-site.js`
- `node scripts/shared-files.js`: compare its short hash with the Help line of an installed copy; after a website change to a shared file, the owner runs the Windows app workflow (see "Refreshing the download after a website change" in `docs/app/WINDOWS-APP.md`)
